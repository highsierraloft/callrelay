# Contribute to CallRelay

Start with the [development guide](docs/development.md).
Use a separate local checkout and fictional test data.
Do not connect development tests to a personal phone or deployed service.

## Changes

Keep a change focused on one behavior.
Add tests for failures, cancellation, and recovery when they affect that behavior.
Update the guide and example settings in the same change.
Retain upstream notices and the separate Android license.

Before a pull request, run the relevant backend, browser, gateway, and privacy checks.
Describe the problem, the resulting behavior, and the checks that passed.
State any missing handset or platform verification.

## Reports

Use GitHub issues for reproducible bugs and feature requests.
Include the version, platform, expected result, and a reproduction with fake data.
Do not include keys, phone numbers, device serials, recordings, or transcripts.
Use [SECURITY.md](SECURITY.md) for vulnerabilities.
